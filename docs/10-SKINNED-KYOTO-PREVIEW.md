# Skinned fighters and Kyoto: preliminary game pass

This branch now has an in-game review path for the corrected dog GLB, King Croak GLB, and a basic Kyoto Coliseum stage. Choose Ollie and King Croak from the selection screen, then Kyoto Coliseum. The existing four fighters and three arenas remain available. The two original GLBs in `handoff/kyoto-v1/models/` remain the source assets; the runtime copies are in `public/models/`.

`src/game/characters/SkinnedFighter.ts` implements the existing `CharacterRig` interface with `GLTFLoader`, `SkeletonUtils.clone`, an `AnimationMixer`, cloned instance materials, and bone-based strike anchors. `App.tsx` waits for required GLBs before constructing a match. The mixer neutralizes animated Hips / bone_0 translation because `Fighter` owns stage movement and jump physics. The game still owns move timing and hit windows through `moves.ts`. The 16 required state names all bind to clips, and a live dog-versus-frog match has been started locally, but **binding coverage does not mean animation quality is approved**.

Known review work:

- Dog light, heavy, special and air use candidate Mixamo clips. The special uses an unarmed presentation of `Dual Weapon Combo`; weapons are optional. Other dog states reuse sections or held endings and need authored cleanup.
- King Croak's existing game moves remain Tongue Lash, Gullet Toss, Toxic Croak and Royal Belly Flop. The current Elbow Punch and Hook Punch transfers are body-motion placeholders, not completed versions of those moves. The known right-hand/chin clipping and elbow stretch remain. A simple tongue extension now follows the head bone for the light attack, but tongue reach, grab contact and gullet action need visual validation.
- Several reaction and recovery states are provisional clip reuse. Get-up reverses the down animation as a temporary 0.55 s bridge. Validate contact at every `moves.ts` hit window, especially both fighters' foot placement, the frog's floor clearance, and all transitions.
- Kyoto uses a real stone fighting floor and medallion at Y=0, sunset concept art behind the fight, audience art panels, and lightweight falling petals. The camera is constrained during Kyoto attract and intro to avoid an orbit around flat art. This is a stage prototype; tree GLB placement, petal kick-up, crowd animation, and stage profiling remain.

glTF-Transform 4.5.0 is useful as an **offline asset processing tool**, not a rig authoring or retargeting substitute. `inspect` reports the dog at about 467k rendered vertices and the frog at about 50k. A trial `simplify --ratio 0.6 --error 0.001` reduced the dog's rendered vertices to about 280k and the file from 10.64 MB to 7.66 MB while preserving its ten animation names and 33-joint skin. The trial is kept outside the repository and is **not** the game asset: chin deformation and other poses must be compared visually before adoption. A `resample` trial slightly increased dog file size. Meshopt/Draco/KTX2 candidates require matching Three.js loader decoders and A18 hardware tests. Do not apply `optimize` wholesale to a skinned fighter without checking bone names, bind matrices, clips, materials, and animation quality.

Validation so far: `npx tsc --noEmit`, `npm run build`, live browser match construction, and programmatic playback of all 16 state names for both skinned fighters. Those checks do not establish visual polish or mobile performance.
